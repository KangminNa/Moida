# Cairn 보관 형식 (v1)

> Cairn의 내용을 파일 묶음으로 내보내고 다시 들여오는 형식.
> GitHub 동기화 플러그인(`sync-github`), md 내보내기(zip), 복원이 모두 이 형식을 쓴다.
> 읽는 법이 바뀌면 `ARCHIVE_FORMAT`(apps/server/src/modules/platform/archive/archive.query.ts)을 올리고, 복원과 이 문서를 함께 고친다.
> "있으면" 칸이나 새 폴더를 더하기만 하는 변경은 번호를 그대로 둔다: 옛 백업은 그대로 읽히고, 옛 Cairn은 모르는 파일에서 아무것도 쓰기 전에 멈춘다 (번호를 올리면 모든 파일이 한 줄씩 바뀌어 동기화가 저장소를 통째로 다시 쓴다).

## 원칙

- **원본은 DB다.** 이 형식은 이력·백업·옮기기용 사본이다.
- **내용은 전부, 운영 데이터는 빼고.** 작업, 승인함, 기기, 토큰, 알림은 넣지 않는다. 다시 계산되는 값(칸별 해시, 검색 조각, 임베딩, 그래프 스냅샷)도 뺀다.
- **비밀값은 절대 넣지 않는다.** 기기, 토큰, 로그인, 비밀 설정.
- **vault는 비공개 저장소에만.** 공개 저장소로 보낼 때는 `vault/`를 빼고, 공개 저장소에 `vault/`가 이미 있으면 동기화를 멈춘다 (git 이력에 남기 때문).
- **공개 저장소에는 공개한 것만.** 임시·링크만 글과 공개 글에 쓰이지 않는 사진도 비공개 저장소에만 보낸다. 사진은 `assets/`에 내용 해시 이름으로 한 번만 들어간다.
- **id를 지킨다.** 모든 항목은 앞부분(frontmatter)에 `cairn_id`를 가져서, 경로가 바뀌어도 같은 항목으로 되살아난다.

## 폴더

```
cairn.json                                  형식 버전 {"format": 1, "generator": "cairn", "spec": "docs/보관형식.md"}
blog/posts/<연도>/<주소>.md                  글
vault/categories.yml                        그래프 카테고리 (이름, 주소, 색, 순서, 분류 기준, 출처, 고정)
vault/wikis/<주소>.md                        wiki
vault/sessions/<프로젝트>/<날짜>-<주소>.md     세션 (raw). 프로젝트가 없으면 no-project. 노트가 아직 없는 세션도 (본문 없이)
vault/transcripts/<세션 id>/<번호>.md        세션 원문 (쌓인 그대로). 원문은 추가만 하므로 경로가 바뀌지 않는다
vault/graph.json                            선(재료·링크·비슷함)과 출처·고정·사람이 지운 흔적, 고정한 점 위치
assets/<sha256>.<확장자>                     글의 사진. 같은 내용은 한 번만
```

에이전트 실행의 기록(작업 세션, 도구 `cairn-agent`)도 세션 · 원문으로 나간다. 인수인계 메모 표(`vault.run_memos`)는 따로 나가지 않는다: 메모는 원문 안에 있다. 복원한 작업 세션은 세션 id가 대화 id가 되어(`RestoredSession`) 복원 뒤의 실행과 이어지지 않고 새 작업 세션이 생긴다.

보관 형식이 관리하는 경로는 위의 것뿐이다. 저장소의 다른 파일(README 등)은 건드리지 않는다.

## md 파일

옵시디언에서 그대로 열리는 md다. 앞부분 키는 옵시디언 속성과 맞게 평평하게 두고, Cairn 전용 키는 `cairn_` 접두어를 붙인다. 확장은 앞부분, 본문 소제목, 본문 문법 세 군데에서만 한다.

| 종류 | 앞부분 (필수) | 앞부분 (있으면) | 본문 |
|---|---|---|---|
| 세션 | `cairn_format`, `cairn_type: session`, `cairn_id`, `title`, `visibility`, `tool`, `started` | `cairn_wiki`(대표 wiki id), `project`, `tags`, `cairn_pinned`(사람이 고친 칸), `cairn_note: false`(노트가 아직 없다: 본문이 비고 `title`은 null일 수 있다), `cairn_noted_seq`(지금 노트를 쓴 원문의 번호, 0이면 없음) | 고정 소제목 `## 한 일` `## 결정` `## 막힌 점` `## 인용` `## 기타`. 노트가 없으면 비어 있다 |
| 원문 | `cairn_format`, `cairn_type: transcript`, `cairn_id`(원문 id), `cairn_session`(세션 id), `seq`(세션 안의 번호, 1부터), `created` | 없음. 모르는 키는 보관할 칸이 없어 복원이 거절한다 | 수집 훅 · 확장이 올린 대화 글 그대로 (민감정보는 쌓을 때 지웠다). 작업 세션(`tool: cairn-agent`, 2026-11-17)의 원문은 실행 하나: 머리(몇 번째 실행 · 에이전트 · 작업 · 세션 키) + 원문 + `## 인수인계 메모` (개인정보도 마스킹했다) |
| wiki | `cairn_format`, `cairn_type: wiki`, `cairn_id`, `title`, `visibility` | `cairn_category`(id, 비어 있으면 미분류), `cairn_origin`(`ai`·`human`), `cairn_pinned` | 본문 md, 다른 wiki는 `[[제목]]` |
| 글 | `cairn_format`, `cairn_type: post`, `cairn_id`, `title`, `slug`, `status`, `published` | `cairn_main_wiki`, `cairn_ref_wikis`, `tags`, `align`, `cairn_assets`(붙은 사진의 해시) | 본문 md + 글 문법: GFM, `::: center`, `> [!quote]`, 사진 `![설명](/api/files/<해시>)` |

모르는 앞부분 키는 버리지 않는다. 복원할 때 `meta`에 보관했다가 다음 내보내기 때 그대로 돌려준다 (원문 파일은 `meta`가 없어 모르는 키가 있으면 복원을 멈춘다).

노트가 없는 세션인지는 `cairn_note: false`로만 안다: 칸이 모두 빈 노트도 본문이 비므로 "본문이 비었는가"로는 구분되지 않는다. 원문은 크다(한 줄 1,000,000자까지, 대화가 길어질 때마다 새 원문). 내보내기와 동기화가 파일 전체를 메모리에 올리는 것은 [리팩토링계획](리팩토링계획.md) 13장의 후보다.

`cairn_origin`, `cairn_pinned`, `cairn_assets`가 없어도 읽는다. 사람의 것으로 보고(AI가 덮지 못하게), 사진은 본문의 `/api/files/<해시>`에서 찾는다.

아직 파일에 없는 것: 블로그 카테고리·시리즈, 표지, 세션 첨부, 세션의 기기 이름, 원문을 올린 기기. 그 기능이 생길 때 더한다.

## 이력

- 판 하나하나는 파일로 남기지 않는다. 내보낼 때의 **현재 판**만 파일이 되고, 지난 판은 git 커밋 이력으로 본다.
- 커밋 단위: `sync-github`가 5분마다 바뀐 파일을 모아 한 커밋으로 올린다. 바뀐 게 없으면 커밋하지 않는다.

## 복원

두 입구가 같은 길을 쓴다. GitHub는 `sync-github` 플러그인의 `복원 미리 보기`와 `저장소에서 복원`, zip은 `pnpm run restore`(표준 입력, `--apply`로 실제 반영). GitHub 복원에는 플러그인의 `archive:restore` 권한이 필요하다.

- **빈 Cairn에만** 복원한다 (데이터가 있는 곳에 섞어 넣기는 다음). 세션, wiki, 글, 카테고리 중 하나라도 있으면 거절한다.
- 사진은 파일 이름의 해시와 내용이 맞아야 한다. 글과 그래프는 한 트랜잭션으로 들어와서, 실패하면 아무것도 남지 않는다.
- 원문은 들어오는 세션을 가리켜야 하고, 세션 안에서 번호가 1부터 이어지고 같은 내용이 둘이면 안 된다. 노트를 쓴 원문 번호(`cairn_noted_seq`)의 원문도 있어야 한다. 하나라도 어긋나면 어느 파일인지 알리고 멈춘다 (파일을 잃은 묶음일 수 있다). 원문은 다시 지우지 않고 바이트 그대로 들어오며, 해시는 다시 계산한다.
- 그대로 돌아오지 않는 것: 지운 민감정보 표시(판 · 원문), 원문을 올린 기기, wiki와 임시 글의 날짜(id에서 다시 얻음), 지난 판, 소재, 정리·검토 설정, 변경 기록. 복원한 세션은 자리값 기기로 들어와서, 옛 대화를 다시 저장하거나 원문을 다시 올리면 새 세션이 된다.
- 빈 Cairn이 백업이 있는 저장소에 동기화하려 하면 멈춘다: 그대로 맞추면 복원하기 전에 백업이 지워지기 때문이다.
- 순서: 형식 검사 → 무엇이 몇 개 들어오는지 미리 보여줌 → 확인 → 사진 파일 → 한 트랜잭션으로 들여옴.
- 세션·wiki·글은 현재 판을 첫 판으로 되살린다. 노트 없는 세션은 판 없이 되살리고, 원문은 번호 그대로 모두 들어온다.
- 기기는 다시 연결해야 한다.

## 시험

"진짜 데이터로 채운 Cairn → 내보내기 → 새 DB의 빈 Cairn에 복원 → 다시 내보내기 → 바이트까지 비교" 테스트가 있다 (`archive-restore.api.test.ts`). 형식을 바꾸면 이 테스트도 함께 고친다.
