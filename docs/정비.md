# 정비 (maintainer)

> 2차 7단계 (서브나 10장 "성장"). Cairn이 쓰는 AI CLI · 스킬 · 확장을 최신으로 유지하는 순서.
> maintainer 팀(에이전트 팀 템플릿 `maintainer`)의 정비 개발자가 Cairn 저장소의 코드 작업으로 이 순서를 따른다. 사람이 해도 같다.

## 1. 도는 방식

1. **점검 담당**(셸 없음, 공개 읽기)이 스케줄 레시피로 매주 돈다.
   - npm 레지스트리에서 CLI의 최신 버전을 읽는다 (`read_url https://registry.npmjs.org/<패키지>/latest`).
   - 지금 고정 버전과 비교하고 릴리스 노트에서 바뀐 점을 찾는다.
   - 고칠 일이 있으면 답의 끝 "코드 맡기기" 단락에 지시문을 남긴다.
2. 관리자가 그 지시문을 코드 메뉴(code-github)에서 **정비 개발자**에게 맡긴다.
   - 저장소는 Cairn. 정비 개발자는 코드 작업 · 샌드박스에서 돈다.
3. 정비 개발자가 아래 2~5장의 순서로 고치고, 검사를 통과시킨 뒤 PR을 올린다. 머지는 관리자가 한다.

샌드박스의 나가는 길은 `egress/allow.txt`다. GitHub와 npm 레지스트리가 이미 들어 있다.

## 2. AI CLI 새 버전

러너 이미지가 고정한 버전: `Dockerfile`의 `npm install -g @anthropic-ai/claude-code@… @openai/codex@…`.

1. 버전을 올린다.
2. 새 버전의 출력 모양을 확인하고, 견본 시험을 맞춘다. 바뀐 칸이 있으면 읽는 코드를 고친다.
   - 출력: `apps/runner/src/claude-stream.ts` · `codex-stream.ts`
   - 견본 시험: `claude-stream.test.ts` · `codex-stream.test.ts`
3. 인자 · 설정 이름이 바뀌었는지 본다.
   - Claude: `claude --help`
   - Codex: `codex exec --strict-config`. 모르는 설정 이름은 시작부터 실패한다.
   - 고칠 곳: `claude-cli.ts` · `codex-cli.ts`.
   - `codex-cli.ts` 머리의 "설정 값은 Codex <버전>의 --strict-config로 이름을 확인했다"도 고친다.
4. 생각 강도 목록이 바뀌었으면 네 곳을 함께 고친다.
   - 서버: `AgentRuntime.EFFORTS`
   - 러너: `ClaudeCli.EFFORTS` · `CodexCli.EFFORTS`
   - 웹: `TOOL_EFFORTS`
5. 어댑터 계약 시험 `apps/runner/src/ai-tool.test.ts`를 통과시킨다. 계약은 다섯 가지다.
   - 빈 설정 홈
   - 허락한 MCP만 붙는다
   - 비밀이 명령줄에 없다
   - 모델 · 강도가 CLI에 닿는다
   - 셸이 있는 일에는 외부 도구를 붙이지 않는다

## 3. 새 AI CLI 더하기 (예: Gemini CLI)

1. `apps/runner/src/<도구>-cli.ts` · `<도구>-stream.ts`를 쓴다. `AiTool` · `AiStream`의 약속을 따른다.
   - 설정 홈은 작업마다 새로.
   - MCP는 `cairn` · 브라우저 작업의 `playwright` · 허락한 외부 도구 `x-*`만.
   - 셸은 칸의 일에서만.
2. `AiTools.SUPPORTED` · `AiTools.for`에 더한다.
3. 계약 시험의 `ADAPTERS`에 한 줄을 더한다. 더하지 않으면 계약 시험이 실패한다.
4. 서버의 도구 목록 두 곳에 더한다. 마이그레이션의 CHECK가 있으면 새 마이그레이션으로 바꾼다.
   - `Agent.TOOLS`
   - `AiLogin.TOOLS`
5. 웹 로그인이 필요하면 러너의 로그인 명령(`signin-run.ts` · `signin-screen.ts`)을 더한다.

## 4. 스킬과 도구 입력 모양

- MCP 도구의 입력 모양(`<모듈>.tools.ko.json`, 도구의 `inputSchema`)이 바뀌면 그 도구를 쓰는 스킬(`skills/*/SKILL.md`)을 함께 고친다.
- AI에게 가는 지시문의 글은 `skills/cairn-runner/references/prompts.md`에만 둔다.
  - 틀의 이름 · 자리를 바꾸면 콘솔 판은 다시 맞춰야 쌓인다 (`PromptTemplates.assertFits`).

## 5. 브라우저 확장의 사이트 읽기

- 사이트별 읽는 부분은 `apps/extension/src/capture/<사이트>.js`다.
- 사이트의 화면이 바뀌어 대화를 못 읽으면 그 파일과 시험을 고친다.
- 확장 시험은 `pnpm --filter @cairn/extension test`다.

## 6. 끝내기 전에

```bash
pnpm check
pnpm --filter @cairn/runner test
pnpm --filter @cairn/extension test
pnpm test
```

- `pnpm test`는 DB가 있는 곳에서 돌린다.
- PR 설명에 다음 셋을 적는다.
  - 올린 버전
  - 바뀐 점의 근거 주소
  - 돌린 시험
