# 지도 설계안 (지도 플러그인 2차, 2026-11-25 승인)

지금 지도 플러그인(스토어 12.6a)은 회사 하나와 브라우저용 키 하나만 받아 `cairn.map.create`로 핀을 찍는다.
앱을 만드는 AI는 회사 SDK를 직접 넣으려 했고(2026-11-25, "kakao는 config.js에 키를 넣어야 해요"), 주소 → 좌표 · 장소 검색은 길이 없다.
이 문서는 네 회사의 공식 문서를 정리하고, 플러그인 하나가 회사마다 다른 것을 어떻게 감출지 정한다.

## 1. 회사별 정리 (공식 문서, 2026-11-25 조사)

조사 한계: 이 개발 환경의 네트워크가 지도 회사 문서 사이트를 막아, 공식 도메인으로 좁힌 검색의 인용으로 확인했다. **미확인**은 배포 서버에서 실제 키로 확인한다 (5장 MP-0).

### 지금 구현과 어긋나는 것

1. **미리 보기는 `Referrer-Policy: no-referrer`**다 (`_blog/app-screen.ts`). OSM 타일 정책 위반이고, 키 있는 지도도 돌 수 없다.
   문서상 격리(출처 없는 문서) 자체보다 Referer가 없는 것이 실패 원인이다. 그렇다면 기본 도메인 화면도 키 있는 지도가 돌 수 있다 (MP-0에서 확인).
2. **지도 회사 호스트 목록이 세 곳**이다: 웹 `map-config.ts` HOSTS, 서버 `AppManifest.MAP_HOSTS`, 러너 `app-manifest-check.ts`. 하나를 고치면 나머지가 틀린다.
3. **OSM 대신 CARTO 타일**을 쓴다. CARTO 무료 조건은 확인하지 않았다.
4. **주소만 있는 장소는 핀이 안 된다.** AI가 좌표를 지어내거나, 회사 SDK의 검색을 직접 부르려 한다.
5. **표시 의무를 지키는 장치가 없다.** 앱 CSS가 로고 · 출처를 가려도 막지 않는다.

## 2. 정한 방향

- **플러그인은 지금처럼 하나(`map`)**, 안에 회사마다 어댑터를 둔다. `cairn.map` 약속 · OSM으로 바꿔 그리기 · CSP는 한 주인이 있어야 하고, 플러그인끼리는 서로 부르는 길이 없다.
  고르지 않은 것: 회사마다 플러그인(map-kakao · map-naver · map-google). 켜고 끄기는 쉽지만 약속과 대체 그리기가 세 벌이 된다.
- **회사 정보는 파일 하나**(`plugins/map/providers.json`): 키 칸 · 스크립트 주소 · 호스트(script · img · connect · style · font · worker) · 표시 의무 · 서버 API 주소.
  웹(CSP · 로더) · 서버(설정 검사 · 앱 코드의 지도 호스트 거절) · 러너(검사)가 모두 이 파일을 읽는다. 1장의 2번을 없앤다.
- **브라우저 키는 공개 설정, 서버 키는 `secret`**(서버 키로 암호화, 화면 · AI · 앱에 가지 않음). 원칙 8과 같은 결: 비밀은 서버 안에서만 쓴다.
- **주소 · 장소 찾기는 서버가 대신 부른다.** 앱은 `cairn.map.search` · `cairn.map.geocode`만 알고, 서버가 회사의 REST를 서버 키로 불러 같은 모양으로 돌려준다.
- **좌표는 약관이 허락하는 만큼만 남긴다.** 회사마다 `storeDays`(구글 30, 카카오 · 네이버는 확인 전 0 = 저장 안 함)를 두고, 앱 데이터에는 주소를 원본으로 둔다.

## 3. 인터페이스

### 3.1 플러그인 설정 (`plugins/map/cairn-plugin.json`)

| 칸 | 종류 | 공개 | 뜻 |
|---|---|---|---|
| `provider` | select (`osm` · `kakao` · `naver` · `google`) | 예 | 화면에 그릴 지도 |
| `kakaoJsKey` · `naverClientId` · `googleBrowserKey` | text | 예 | 브라우저용 키 (도메인 묶기를 회사 콘솔에서) |
| `kakaoRestKey` · `naverClientSecret` · `googleServerKey` | secret | 아니오 | 주소 · 장소 찾기용 서버 키 |
| `searchProvider` | select (`none` · `kakao` · `naver` · `google`) | 아니오 | 찾기에 쓸 회사. 그리는 회사와 달라도 된다 (구글은 약관상 구글 지도와 함께일 때만 고를 수 있게 막는다) |
| `dailyLimit` | text (숫자) | 아니오 | 서버가 하루에 부르는 찾기 횟수 상한. 기본은 무료량의 절반 |
| `osmTiles` | select (`osm` · `carto`) | 예 | 키 없는 지도의 타일 |

지금의 `key` 칸은 `provider`에 맞는 브라우저 키 칸으로 옮긴다 (설정을 읽을 때 한 번 옮기고 지운다).

### 3.2 앱 코드가 쓰는 것 (`cairn.js`)

```js
cairn.map.provider                         // 'osm' | 'kakao' | 'naver' | 'google'
cairn.map.create(자리, {                     // 지금과 같다 + 아래 둘
  places: [{ lat, lng, name } | { address, name }],   // 주소만 있으면 서버 geocode로 좌표를 받아 핀
  cluster: true,                           // 핀이 많을 때 묶기 (카카오 clusterer · 구글 markerclusterer · leaflet.markercluster)
})
cairn.map.search(q, { near?: { lat, lng }, size? })   // → { places: [{ name, address, lat, lng, provider, id }], attribution }
cairn.map.geocode(address)                 // → { lat, lng, address } | null
cairn.map.reverse(lat, lng)                // → { address } | null
```

- 찾기는 서버 경로 `GET /<앱>/_/map/search?q=…` · `/_/map/geocode?address=…` · `/_/map/reverse?lat&lng`(앱 주소 아래라 격리된 화면에서도 같은 출처의 `cairn.data`처럼 부른다).
- 오류는 `cairn.data`와 같은 모양 (`status` · `code`): 찾기 회사 없음 `404 map.off`, 하루 상한 `429 map.limit`, 회사 오류 `502 map.upstream`.

### 3.3 서버

- `platform` 또는 `blog`에 `MapSearchGateway` 하나: 회사마다 요청을 만들고 응답을 `{ name, address, lat, lng, id }`로 맞춘다. 키는 플러그인 secret에서만 꺼낸다.
- `MapSearchQuery`: 앱이 공개인지(또는 토큰 주소인지) 확인 → 방문자 IP마다 분당 30회 · 공간 하루 `dailyLimit` → 메모리 캐시(같은 질문 10분, `storeDays`가 0이면 메모리에만) → 게이트웨이.
- 쓰는 표: 없음. 하루 횟수는 서버 메모리에 세고 날마다 지운다. 재시작하면 0부터 다시 세므로 기본 상한을 무료량의 절반으로 잡는다.
- 일꾼 도구 `map_geocode(addresses[])`: 앱을 만들 때 주소 목록을 좌표로 바꿔 미리 확인한다. 결과는 확인용이고 앱 코드에 좌표를 박지 않는다 (약관의 저장 기간).

### 3.4 웹 · CSP

- `map-config.ts`가 `providers.json`의 호스트로 CSP를 연다. 구글은 공식 권장이 nonce + `'strict-dynamic'`이라, 구글을 고른 화면만 그 방식으로 바꾼다 (`appHeaders`에 nonce).
- 미리 보기 화면의 `Referrer-Policy`를 `no-referrer`에서 `strict-origin`으로 바꾸고, 지도 스크립트 · 타일에도 `strict-origin`을 붙인다 (Leaflet은 `referrerPolicy` 옵션). 미리 보기 주소의 토큰은 경로에 있어 출처만 보내면 새지 않는다. 이것으로 1장의 1번을 푼다. 회사 SDK가 스스로 부르는 요청은 문서의 정책을 따르므로 요소마다가 아니라 문서에서 바꾼다.
- 표시 의무: `cairn.map`이 그린 뒤 로고 · 출처 요소가 보이는지 확인하고, 앱 CSS가 가렸으면 콘솔(미리 보기)에 경고를 낸다. 러너 검사는 앱 CSS에 `.leaflet-control-attribution`을 숨기는 규칙 · 로고 클래스 `display:none`이 있으면 문제로 낸다.

### 3.5 AI가 보는 안내

- `cairn-make` 스킬: 장소는 `{ address, name }`으로 넘기면 된다 · 검색 상자는 `cairn.map.search` · 키를 묻지 않는다 (지금 규칙 그대로).
- 앱 코드 검사(서버 · 러너)는 지도 회사 호스트를 `providers.json`에서 읽어 거절한다 (지금 하드코딩한 목록을 대신).

### 3.6 MP-1에서 정한 것 (2026-11-25)

- 웹(`_blog/map-config.ts` · `cairn-map.ts`)은 `providers.json`을 바로 가져온다 (웹 빌드에 `plugins/`가 들어 있다).
- 서버(`AppManifest.MAP_HOSTS`)와 러너(`AppManifestCheck.MAP_HOSTS`)는 `src` 밖을 가져오지 않고, 러너 이미지에는 `plugins/`가 없다.
  그래서 거절 목록을 옮겨 적고, 테스트(`app-manifest.test.ts` · `app-code-check.test.ts`)가 `providers.json`의 `sdkHosts`와 맞춰 본다. 한쪽만 고치면 테스트가 깨진다.
- 플러그인 설정은 `provider` · `kakaoJsKey` · `naverClientId` · `googleBrowserKey` · `osmTiles`. 옛 `key`는 마이그레이션(`20261125130000_platform_map_plugin_keys.sql`)이 고른 회사의 칸으로 옮기고 지운다. 서버 키 · `searchProvider` · `dailyLimit`은 MP-2에서 더한다.
- 키 없는 지도의 기본 타일은 CARTO에서 OpenStreetMap 공식 타일로 바꿨다 (정책을 확인한 쪽). CARTO는 `osmTiles: carto`로 고를 수 있다.

### 3.7 MP-2에서 정한 것 (2026-11-25)

- 찾기는 지도 플러그인의 서버 코드(`plugins/map/server/`)가 한다: 코어 모듈을 새로 두지 않고 기능 패키지의 `api`(`/api/p/map/search` · `geocode` · `reverse`, `Operation.ANYONE`). 서버 키는 플러그인의 `secret` 설정에서만 꺼낸다.
- 곳마다 분당 상한을 세려고 플러그인 API 0.11에 `work.place`(요청 IP를 한 곳으로 묶은 열쇠)와 `AttemptLimiter` · `TooManyRequests`를 더했다. 웹이 방문자 주소(x-forwarded-for)를 넘기고 서버는 trust proxy로 읽는다.
- 앱 코드는 `<앱 주소>/_/map/<동작>`(웹)으로 부른다: 앱 도메인에서는 `/api`가 닫혀 있어서다 (`cairn.data`와 같은 길). 웹은 정해 둔 칸(q · lat · lng · size · address)만 넘긴다.
- 회사 서버 API 주소는 `providers.json`이 아니라 게이트웨이(`MapSearchGateway.BASES`)에 둔다: 서버만 쓰고, 테스트가 테스트용 웹 서버 주소로 바꿔 넣는다. 회사마다 찾기 키 칸 · 장소 찾기 여부 · 하루 기본 상한 · 출처 이름은 `providers.json`의 `search`.
- 네이버 Maps에는 장소 이름 찾기가 없어 `search`도 주소 찾기로 대신한다. 네이버 서버 API 주소는 새 Maps 상품의 `maps.apigw.ntruss.com` (MP-0에서 확인).
- 구글 찾기는 그리는 지도(`provider`)도 구글일 때만 켜진다 (지오코딩 결과는 구글 지도에, 구글 약관).
- 같은 질문은 서버 메모리에 10분 기억한다(500개까지, 오래된 것부터 지움). 하루 횟수도 메모리라 다시 켜면 0부터: 기본 상한을 무료량의 절반쯤으로 (카카오 50000 · 네이버 1000 · 구글 100).

### 3.8 MP-3에서 정한 것 (2026-11-27)

- 묶기는 `cairn.map.create(자리, { places, cluster: true })`. 회사마다 묶는 라이브러리: OpenStreetMap은 Leaflet.markercluster 1.5.3, 카카오는 SDK의 `libraries=clusterer`, 구글은 `@googlemaps/markerclusterer` 2.5.3. 바깥 라이브러리는 unpkg에서 버전을 고정하고 SRI(sha384)로 받는다 (unpkg는 이미 Leaflet 때문에 CSP에 있다). 네이버는 공식 묶기 라이브러리가 SDK에 없어 묶지 않는다. 라이브러리를 받지 못하면 묶지 않고 핀을 그린다.
- 표시 의무: 지도 회사의 출처 · 로고는 지도 위에 남아야 한다 (OSM 출처 표시 정책, 카카오 · 네이버 · 구글 약관). 두 겹으로 본다: 러너 검사(`MapCreditCheck`)가 앱 코드의 CSS에서 출처 · 로고 칸을 숨기는 규칙을 찾으면 거절하고, `cairn.map`이 그린 뒤 2초에 OSM 출처 칸이 보이는지 보고 아니면 콘솔에 경고를 남긴다 (회사 SDK가 그리는 로고는 회사 코드가 지킨다).
- 콘솔 › 운영 › 지도 화면(플러그인 메뉴)이 오늘(UTC) 찾기 횟수 · 하루 상한 · 남은 수를 보인다. 서버 동작 `GET /api/p/map/usage`(관리자만). 횟수는 서버 메모리라 다시 켜면 0부터다 (3.7).

## 4. 버티는 법 · 위험

- 회사가 키 이름 · 주소를 바꾸면 `providers.json` 한 줄만 고친다 (네이버 `ncpClientId` → `ncpKeyId`, 지도 상품 이전 같은 일).
- 회사 지도를 못 받으면 지금처럼 OSM으로 그린다. 찾기 회사가 막히면 `cairn.map.search`가 오류를 내고 앱은 목록을 그대로 둔다.
- 무료량을 넘기면 돈이 나간다: 서버가 하루 상한에서 멈추고, 콘솔 플러그인 화면에 오늘 쓴 횟수 · 상한을 보인다.
- 방문자가 찾기를 마구 부를 수 있다: IP마다 분당 상한 + 공개 앱 · 토큰 주소만.
- 남는 위험: 카카오 · 네이버가 Referer로 도메인을 보는지 Origin으로 보는지는 확인 전이다. Origin을 보면 격리된 화면에서는 여전히 OSM이다.

## 5. 단계

| 단계 | 하는 일 | 확인 |
|---|---|---|
| MP-0 | 배포 서버에서 실제 키로 확인: 회사 × (앱 도메인 · 기본 도메인 · 미리 보기)에서 지도가 뜨는지, CSP report-only로 실제 호스트 모으기 | 관리자 (배포 서버) |
| MP-1 (끝, 2026-11-25) | `providers.json` · 호스트 세 곳 합치기 · 출처만 보내기 · 설정 칸 나누기와 옛 `key` 옮기기 | 단위 테스트 · 마이그레이션 확인 |
| MP-2 (끝, 2026-11-25) | 서버 찾기(`MapSearchGateway` · `MapLookup` · 경로 · 상한 · 기억) + `cairn.map.search/geocode/reverse` + `places`의 주소 | 회사 응답은 테스트용 웹 서버로 |
| MP-3 (끝, 2026-11-27) | 묶기(`cluster`) · 표시 의무 확인 · 러너 검사 · 스킬 · 플러그인 화면의 오늘 쓴 횟수 | 브라우저 확인 |
| MP-4 | 일꾼 도구 `map_geocode` · 문서(스토어 12.6a) | 러너 테스트 |

나중에: 길찾기(네이버 Directions · 구글 Routes), 정적 지도 그림(서명 · 약관의 그림 저장 금지를 따로 봐야 함), VWorld(국토부, 키 + 도메인) 타일.
